# 教学小镇「课程实操化」改造计划

## Context
用户反馈：第一阶段很多课「只读卡 + 答一题」，缺乏游戏与实操。确认方向：**10 课全改**（t1/t2/t3/t5/t7/t8/t9/t12/t13/t14），**多课要求真实交易**（t10/t12/t13/t14，带现金/持仓兜底，绝不卡关）。约束不变：评价基于学习行为而非盈亏；奖励只解锁工具；K线只教读图；简化 A 股规则。

关键事实：main.js 的 `dispatch` 有 `default: lessons.onAction(ctx, type, payload)` 转发分支——新增 dispatch 类型（bookRow/candlePick/openBoard/indexInfo）**无需改 main.js 分发逻辑**，只需给 renderTown 加第 6 个回调。

## 一、逐课改造（每课 1 个亮点操作）

| 课 | 新操作 | 机制 |
|---|---|---|
| t1 股票是什么 | 读完概念卡后算账输入：「发行 100 万股 × 8 元，筹资多少万元？」（答 800） | 新增 `runQuizNum` |
| t2 市值 | 点两建筑（已有）→ 概念卡 → 输入萤火市值（亿元，±2% 容忍）→ 保留原选择题 | runQuizNum + 现有 quiz |
| t3 分红 | 不再自动弹窗：day3 toast 提示，须**点击小镇公告栏**才弹分红预案 → 算账输入「持 100 股红利多少元」（答 20）→ 完成 | 公告栏点击 `openBoard` |
| t5 盘口 | 先**点击盘口「卖一」那一行**（点对才进答题；点错 toast 提示不惩罚），再答原选择题；任务卡备「直接答题」兜底按钮 | 盘口行点击 `bookRow` |
| t7 读图 | 改为**点击 K 线图上涨幅最大的那根蜡烛**（判定用纯函数 `bestGainDay`）；备「点不准？改成选择题」按钮走原 quizChart | 蜡烛点击 `candlePick` |
| t8 指数 | 顶栏「小镇综指」变可点 → 弹权重分解（三股市值占比）→ 再答原选择题 | `indexInfo` 弹窗 |
| t9 除息 | exdivExplain 保留自动弹，示例账后改为**输入自己实际到账红利**（持股×0.2，无持仓用 100 股例账兜底——已有逻辑） | runQuizNum |
| t10 传闻 | 调查决策（已有）后：选「买入」须**真实成交 1 笔松果买入**（数量自定）；选「观察」直接完成。现金不足被拒 → 说明弹窗后完成 | 复用 placeOrder/orderRejected |
| t12 仓位 | 冲击对比账弹窗后，任务要求**真实买入 1 手河狸物流**（已持有≥100 股自动满足）→ 答题。兜底：任务卡「现金不足？用例账代替」→ 算账输入「全仓松果今天约亏多少元」（±2%）→ 答题 | placeOrder + runQuizNum 兜底 |
| t13 摊平 | 先做**摊平计算器**（9.50 买 100 股 + 7.90 补 100 股，平均成本？答 8.70）→ 真实选择：选「补仓」**真实市价买 1 手松果**（现金不足 → 「无法真实补仓，用例账完成」说明）→ 选理由 → 讲解 → 完成 | runQuizNum + placeOrder |
| t14 FOMO | day33 不再自动弹窗：toast 提示，须**先点公告栏查证**（弹「传闻无官方公告」）→ 追/不追选择：选「追买」尝试**真实买 1 手萤火**（设计路径现金大概率不足 → 「满仓的代价」教学弹窗，本身即一课）→ 选理由 → 毕业 | openBoard + placeOrder |

## 二、新组件最小接线

1. **runQuizNum**（lessons.js）：复用 `showModal`，body 内 `<input type="number">`，判定用纯函数 `numOk(v, ans, tolPct=0.02)`（放 util.js）；答错重渲染带提示（同 runQuiz 不惩罚风格），答对 `onCorrect`。
2. **bestGainDay(market, symbol, day)**（market.js）：从 quizChart 抽出，quizChart 与 candlePick 判定同源。
3. **盘口行点击**（ui.js）：bookHTML 每行 `<tr data-row="ask1..5/bid1..5">`；bindPanelEvents book 分支绑 click → `ctx.dispatch('bookRow', { symbol, row })`。
4. **K线蜡烛点击**（ui.js）：candleSVG 每根加透明命中层 `<rect class="candle-hit" data-day=".." fill="transparent">`；bindPanelEvents chart 分支绑 click → `dispatch('candlePick', { day })`。
5. **公告栏点击**（town.js/main.js）：board() 外层 `<g class="bld" data-board="1">`；renderTown 第 6 参 `onBoard`；main.js 传 `() => dispatch('openBoard')`。`onAction('openBoard')`：t3/t14 走对应流程；其他任何时候弹当日 boardText 详情（点击必有反馈）。
6. **综指点击**（ui.js renderStats）：综指包成 `<button id="stat-index">`，渲染后绑 click → `dispatch('indexInfo')` → 弹三股市值/权重；t8 时弹窗带「开始答题」按钮。

### maybeAuto 调整
- t3：day≥3 不再自动弹，改为 toast 一次「公告栏贴出了新公告」（flags 防重复）
- t14：day≥33 不再自动弹 fomoModal，改为 toast 一次「传闻又起——先去公告栏查证」
- t12/t13 保持自动弹（新闻冲击/算账器是时点事件）

## 四、无头测试补充（node tests\town-tests.mjs）
- `bestGainDay(mkt,'pinecone',10)` 与暴力逐日计算一致
- `numOk`：精确值过、±1.9% 过、±2.1% 拒、NaN/空拒
- 红利 `round2(100×0.2)===20`；摊平成本 `(9.5×100+7.9×100)/200===8.7`
- day25 松果 pct≈−6%、三家等权 avg 绝对值更小
- `candleSVG(bars)` 输出含 `candle-hit` 数 === bars.length 且 data-day 正确（ui.js 无顶层 DOM 访问，node 可 import）
- bookHTML 输出含 `data-row="ask1"`
