# 《股市小镇》第一阶段原型实施计划

## Context

项目目录当前为空（仅含《股票学习网页游戏-项目需求与设计.md》v0.1）。本次目标：按文档第 9 节完成**第一阶段「虚构教学市场」完整可玩原型**——1 个小镇、3 家虚构公司、教学大纲前 3 阶段、模拟交易、1 次升级、1 个综合事件、1 次完整复盘，20–30 分钟体验。

已与用户确认的决策：

* 技术栈：**纯 HTML/CSS/JS**（ES Modules，无构建，localStorage 存档，可部署 GitHub Pages）

* 画面：**原创 SVG + CSS**（俯视小镇、简洁造型、柔和配色）

* 移动端：**一套响应式代码**（PC 左右分栏 / 手机上下堆叠 + 抽屉面板）

* 范围：完整第一阶段原型

文档边界遵守：不做真实行情、不接 API、不做基金/期货、不用 AI 决定涨跌、奖励不得提供收益加成；第一阶段的简化交易规则需在界面中明确标注「虚构教学市场，非真实规则」。

## 核心数据设计（data.js）

**3 家虚构公司**（数值设计成教学对照组）：

| 公司   | 股价      | 总股数     | 市值    | 教学用途          |
| ---- | ------- | ------- | ----- | ------------- |
| 松果食品 | \~8 元   | 1 亿股    | \~8 亿 | 「股价低≠公司便宜」反例  |
| 河狸物流 | \~45 元  | 2000 万股 | \~9 亿 | 对照组           |
| 萤火科技 | \~120 元 | 500 万股  | \~6 亿 | 「股价最高但市值最小」反例 |

**市场脚本**：固定种子（存档中保存 seed，可复现），30 个模拟交易日的价格路径 = 预设趋势 + 种子噪声；第 8 天触发综合事件（松果食品「销量大涨」传闻 + 隐藏的成本上升问题，第 15 天财报揭示）。

**课程任务定义**（每课含：前置、目标、情境、操作、反馈、完成判定函数、常见误解纠正、奖励，对齐文档 7.1 模板）。

## 引擎设计（market.js）

* **时间**：以「交易日」为单位推进，玩家点击「下一天」或自动播放（可暂停）；阅读教学内容时不强制倒计时。

* **交易规则（界面标注为虚构教学规则）**：一手 100 股整数倍；支持市价/限价委托；佣金 0.1%、最低 1 元；限价单价格未达则保持「未成交」，可撤销；**未成交委托绝不变成持仓**。

* **撮合**：市价单按当日价格成交；限价买单 ≥ 当日最低价则成交（简化假设，界面注明）。委托单生成唯一 ID，结算幂等，重复点击不重复扣款/发奖。

* **账户**：现金、持仓（股数、成本价）、冻结资金、账户总值实时一致。

## UI 设计

* **PC 布局**（≥900px）：左侧 SVG 小镇 + 当前任务卡；右侧 Tab 面板（公司档案 / 交易台 / 行情终端，随课程逐步解锁）；底部事件时间线 + 操作记录 + 复盘入口。

* **手机布局**（<900px）：小镇压缩为顶部横幅；面板全宽 Tab；时间线收进底部抽屉；触控目标 ≥44px。

* **小镇 SVG**：研究室（2 级升级外观）、三家公司建筑、公告栏；经营事件可视化（货物堆积、货车动画）只表现经营现象，不直接映射股价（文档 5.2）。

* **涨跌展示**：↑/↓ 符号 + 数值 + 文字三重表达，不只依赖红绿色（文档 5.2）。

* **行情图**：SVG 手绘 K 线 + 成交量柱（第 3 课解锁前只显示价格列表）。

## 第一局流程（lessons.js 任务链，对应文档第 9 节）

1. 进入小镇，看到松果食品与萤火科技股价差异 → 引导点击公司档案
2. 概念卡：股数 × 股价 = 市值 → 交互判定：回答「哪家公司总价值更高」（答错给出针对性纠正）
3. 完成比较 → **解锁交易台** + 研究室升级动画 + 股东证图鉴
4. 概念卡：委托 vs 成交 → 先引导挂一个不会成交的限价单（观察「未成交」状态），再下市价单成交 → 判定：解释未成交原因
5. 推进时间数天，观察现金/持仓/价格变化
6. **解锁行情终端** → 概念卡：涨跌幅、K 线、成交量 → 判定：从图表读出「哪天涨得最多」（强调读图≠预测）
7. 综合事件：松果食品传闻 + 两次调查机会（销售数据 / 成本数据二选二），决定是否买入
8. 财报揭示 → **复盘界面**：时间线回放「当时可见信息 → 你的操作 → 结果」，评价基于是否查看成本数据、是否区分传闻与事实，**不按盈亏判定**
9. 显示第 4–8 阶段课程预告（占位，不实现）

## 存档（state.js）

* localStorage 单 key（如 `stock-town-save-v1`），每次状态变更自动保存

* 含：seed、当前天数、现金、持仓、委托、已完成任务、已解锁项、操作记录（供复盘）

* 提供「重新开始」按钮；已解锁能力不因亏损清零

## 验证方式

1. 本地起静态服务，用 Chrome DevTools MCP 打开页面，完整走一遍第 1–9 步流程
2. 核对：现金+持仓市值+冻结资金 = 账户总值；未成交委托不产生持仓；重复点击不重复结算
3. 刷新页面验证存档恢复；点「重新开始」验证重置
4. DevTools 模拟手机视口（如 iPhone 14）检查布局、触控目标、无面板遮挡
5. 对照文档 11.2 教学验收三条：市值解释、委托≠成交、读图不预测
