# 第三阶段实施计划：实时行情模拟交易（AKShare 真实数据版）

## Context

第一、二阶段已完成并全部验证（教学小镇 + 4 个历史风格回放剧本，30/30 无头测试 + 浏览器全流程 + 移动端）。用户决定进入第三阶段：**接入真实 A 股行情，做实时模拟交易**。

用户已确认的四项决策：

1. **数据源**：真实行情，用 AKShare（Python 数据接口库）。
2. **服务端形态**：先在本机用 Python 运行一个本地行情服务；架构上预留日后公网部署的能力（API 凭证不出服务端、前端只访问本服务）。
3. **玩法范围（全选）**：盘中盯盘 + 虚拟交易；多股票自选股（3–5 只）；每日复盘报告；与回放模式打通——**完成全部 4 个历史剧本（有结算记录）后才解锁实时模式**。
4. **工作模式**：沿用第二阶段流程——先本计划文档 → 用户批准 → 再实施。

需求文档 §10.3 约束（必须保留）：API 凭证不进浏览器；行情来源可替换；界面披露数据更新时间与延迟；只有日线/快照数据时不假装知道盘中逐笔；教学评价不按盈亏论对错。

**前置检查项（实施第一步做，不通过则暂停并回报）**：核实 AKShare 的使用授权与公开展示条款。本阶段先按「本地自用、不公开部署」推进；若日后要公开展示，需重新核实授权或替换为已授权数据源（架构上数据源可替换，替换成本可控）。

## 目标（对应需求文档第 9 节第三阶段）

在现有游戏上新增「实时模拟」模式：跟随真实市场时间，用虚拟资金对真实 A 股进行模拟买卖；行情自动刷新；每日收盘后生成复盘报告；界面明确披露数据来源、更新时间与延迟。

## 架构与文件

整体结构：**浏览器前端（现有，纯 HTML/CSS/JS） ↔ 本地 Python 行情服务（新增 server/） ↔ AKShare**。

### 服务端（新增 `server/`，Python）

| 文件 | 职责 |
|---|---|
| `server/app.py` | HTTP 服务（用标准库 `http.server` 或 Flask，优先零依赖/轻依赖），提供下列 API；CORS 只允许本地前端来源 |
| `server/quotes.py` | AKShare 调用封装：个股日线历史、当日快照；统一字段格式；失败重试与错误分类 |
| `server/cache.py` | 磁盘缓存（`server/cache/` 目录，JSON 文件）：日线按「日期+股票」缓存不再变的历史数据；当日快照短 TTL（如 60 秒）缓存，避免频繁请求上游 |
| `server/config.py` | 端口（默认 8500）、自选股清单以外的可调项、数据源开关（预留替换点） |
| `server/requirements.txt` | `akshare`（及 pandas 依赖）；如用 Flask 则列入 |

API 端点（全部 GET，JSON 返回，统一 `{ ok, data, error, meta }` 结构）：

| 端点 | 说明 | 缓存策略 |
|---|---|---|
| `/api/health` | 服务存活 + AKShare 可用性自检 | 不缓存 |
| `/api/history?code=600519&days=120` | 个股近 N 天日线（开高低收、成交量、日期），用于 K 线图 | 历史日期永久缓存；当日数据短 TTL |
| `/api/quote?code=600519` | 当日快照：现价、今开、涨跌幅、昨收、成交量、数据时间戳 | 60 秒 TTL |
| `/api/quotes?codes=600519,000001,...` | 批量快照（自选股列表用，一次请求） | 60 秒 TTL |
| `/api/calendar` | 今日是否交易日 + 最近交易日（用 AKShare 交易日历） | 当日缓存 |

每个响应的 `meta` 必须带：`source: "akshare"`、`fetchedAt`（服务端取到数据的时间）、`cached`（是否来自缓存）、`adjust`（复权口径，见下）。前端据此披露。

**失败降级**：AKShare 请求失败/超时 → 返回 `ok:false` + 错误类型（网络失败/非交易日/代码不存在/上游限流）；已缓存的旧数据可标 `stale:true` 兜底返回，界面显示「数据可能过期」。

**预留公网部署**：所有 AKShare 调用只发生在服务端；前端不直接接触任何凭证与上游。日后部署到公网服务器时，只需把前端 `API_BASE` 从 `http://127.0.0.1:8500` 改为服务器地址，并加一层访问令牌（本阶段不实现，只在 config.py 留注释位置）。

### 前端（现有项目内新增/修改）

| 文件 | 改动 |
|---|---|
| `js/live.js`（新增） | 实时模式纯逻辑引擎（不依赖 DOM，可无头测试）：虚拟账户（现金/持仓/委托）、T+1、涨跌停限制（±10%，ST 标的不纳入自选股以避免 ±5% 复杂度，界面注明）、费用（沿用回放模式：佣金 0.025% 最低 5 元 + 卖出印花税 0.05%）、以快照价成交的模拟规则、每日收盘结算、复盘报告生成（当日操作、盈亏、持仓变化、与买入持有对照）、交易日历处理（非交易日提示） |
| `js/live-ui.js`（新增） | 实时模式界面：自选股管理（3–5 只，添加/删除，常见股可搜索代码）、行情看板（每只股票现价/涨跌幅/迷你 K 线/数据时间戳）、交易面板、持仓与账户总览、每日复盘报告页、数据披露栏（来源/更新时间/延迟/「模拟成交以快照价近似，不代表真实排队成交」） |
| `js/main.js` | 模式路由加 `live` 分支；入口屏加第三张模式卡片（未解锁时置灰并显示解锁条件）；「切换模式」往返逻辑不变 |
| `js/state.js` | 存档加 `live` 分支：`{ cash, positions, trades, watchlist, dayReports, lastTradeDate, unlocked }`；`load()` 补默认值 |
| `index.html` / `css/style.css` | 实时模式需要的容器与样式（复用现有面板/K 线样式为主） |

**解锁条件**：`st.replay.history` 中 4 个剧本每个都至少有 1 条结算记录 → `st.live.unlocked = true`。入口屏和模式卡片上都显示进度（如「历史剧本完成 3/4」）。未解锁时点击给出提示，不进入。

**复用**：`ui.js` 的 `candleSVG`（已支持停牌渲染）、modal、toast；`replay.js` 的费用/常量定义（提取共用或重新 export，不复制数字）；`util.js` 的 round2 等。

**与回放模式打通**：复盘报告页的格式沿用回放结算页的对照思路（本次操作 vs 买入持有）；从实时模式可一键跳到回放模式（切换模式现有机制）。

## 行情口径与披露（界面固定显示）

- 数据源：AKShare（上游为公开行情接口，非实时 Level-1 推送）
- 更新机制：快照约 60 秒刷新一次；界面显示「数据时间：HH:MM:SS（约 X 秒前更新）」
- 延迟说明：界面固定文案「行情为快照数据，可能有 1–5 分钟以上延迟；模拟成交以快照价近似，不代表真实市场的排队成交」
- 复权口径：历史 K 线用**前复权**（qfq，便于连续看图）；交易与资产计算用**未复权名义价** + 现金分红入账（与第二阶段口径一致：分红不增加总资产）。界面披露该口径。若 AKShare 前复权接口在本阶段验证不稳定，降级为未复权 + 除息日提示，并在界面注明
- 非交易日/休市：显示「今日非交易日」或「已收盘」，禁止下单但可查看与复盘

## 模拟交易规则（实时模式，界面标注「模拟规则 · 简化版」）

- 初始资金 100,000 元（独立于教学模式与回放模式存档）
- 自选股 3–5 只：用户从预设的常见流动性好的股票池（约 20 只，大盘蓝筹为主，避免 ST/退市风险标的）挑选；也可输入代码添加（服务端校验存在性）
- 交易时间：仅交易日 09:30–11:30、13:00–15:00 可下单（以本地时间判断 + 服务端交易日历校验）；其余时间委托提示「非交易时段」，不收也不排队（简化，界面注明）
- 成交价：下单时取最新快照价（买入价不得低于快照价 ×(1−10%) 即跌停校验、涨停不可买/跌停不可卖，规则同回放模式）
- T+1：当日买入次日才可卖
- 费用：佣金 0.025% 最低 5 元；卖出印花税 0.05%（与回放模式一致）
- 每日收盘（15:00 后首次打开或手动触发）生成当日复盘报告：当日操作明细、账户总值变化、持仓盈亏、与「当日不操作」对照、一句话复盘提示（不评价对错，只呈现事实与问题）

## 环境准备（一次性，写给用户的操作步骤）

1. 确认 Python 已安装：`python --version`（需 3.9+）
2. 安装依赖：`pip install -r server/requirements.txt`（即 akshare 等；如超时可用 `pip install -r server/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`）
3. 启动行情服务：`python server/app.py`（默认 http://127.0.0.1:8500 ，启动时自动跑一次 /api/health 自检并打印结果）
4. 启动前端（沿用现有方式）：`python -m http.server 8137`，浏览器打开 http://127.0.0.1:8137
5. 停用：两个终端窗口各自 Ctrl+C

以上命令也会写进 `server/README.md`（就这一份简短说明，不另写文档）。

## 降级与异常文案

| 场景 | 行为 |
|---|---|
| 行情服务未启动 | 实时模式首页显示「未检测到本地行情服务」，附启动命令（可复制），提供「先去玩回放模式」按钮；不白屏不报错堆栈 |
| AKShare 请求失败 | 该股票卡片显示「行情获取失败，X 分钟后自动重试」，其余股票不受影响；交易禁止（无价格不成交） |
| 非交易日/休市 | 显示状态条，禁止下单，可看历史与复盘 |
| 数据 stale（缓存兜底） | 卡片角标「数据可能过期」，交易禁止 |
| 浏览器关掉若干天后再打开 | 按最后记录日期补齐错过的交易日的日结（用历史日线补算资产），生成「缺席期间回顾」 |

1. `node --check` 全部 js 文件
2. 无头测试（Temp 目录，参照 replay-test.mjs 方式）：T+1、涨跌停拒单、费用恒等式、日结数字、复盘报告内容、缺席多日补算、解锁条件判定（4/4 才解锁）
3. 服务端测试：启动 server 后 curl 各端点（真实股票代码、错误代码、批量）；杀掉 AKShare 网络模拟失败降级
4. Chrome DevTools MCP 全流程：完成解锁 → 添加 3 只自选股 → 买入 → 刷新页面（存档恢复）→ 卖出（T+1 拦截 → 推进日期后成功）→ 生成复盘报告 → 停掉 server 验证降级文案 → 控制台零错误
5. 移动端 375px 布局检查

## 验收标准

- 4 个剧本全部完成前实时模式不可进入，进度显示正确；完成后解锁
- 行情卡片始终显示数据时间与「快照近似成交」披露；stale/失败状态有明确文案
- 非交易时段/非交易日/涨停/跌停/停牌（历史日线缺口）均有拒单文案
- 账户恒等式成立（现金 + 持仓市值 = 总资产，费用逐笔可查）；复盘报告数字与交易记录一致
- 服务未启动时实时模式整体降级为说明页，不影响教学/回放模式
- 控制台零错误；移动端布局不破
